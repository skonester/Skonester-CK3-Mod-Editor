# CK3 1.20 compatibility

The editor was checked against the supplied `ck3-mod-base/base/game` tree,
tracked as **1.20.0.3 “Crozier”** in `base/.ck3-version.json`.
The game’s database `.info` files are the schema reference; the repository’s
`1.20.0.2.md` report helped identify changes from 1.19.0.6.

## Supported changes

| Editor | 1.20 behavior |
| --- | --- |
| Character | Separate `faith` and `rite` fields. Existing `religion` aliases keep their spelling. A new character may set a rite without a faith. |
| Religion | Read and save family, graphical faith, and piety icon group inside `religion_details`. New definitions use the 1.20 shape. |
| Faith | Read standalone `faith_types` definitions. Save nested `faith_details`, main rite, block-valued doctrines and tenets, and ordinary/eminent holy sites. New faiths may use a base-game religion. |
| Rite | Create and edit `rite_types` definitions: parent faith, color, icon, founder, create/convert flags, doctrines, and tenets. Includes favorites, recents, drafts, and links to faiths and character history. |
| Title | Read top-level succession laws and history in subfolders, including `history/titles/ce3`. Nested mod history remains editable with its relative path preserved. |

Doctrine groups collect members from each doctrine’s `doctrine_group_type` and
sort by `index`. Tenets are loaded separately from `tenet_types`.
File overrides, definition overrides, and `replace_path` apply to the new databases.
The character rite picker includes implicit same-id rites for standalone faiths
without scripted rites. These are edited through the Faith Editor.

Legacy nested faiths and their scalar doctrine/holy-site lists remain readable
and keep their format when saved. This update does not automatically migrate
existing mod files. New content follows the schema detected from the selected
game/mod data.

## Preservation and scope

Saves leave unedited content intact, including conditional tenet selections,
dynamic rite names/descriptions, cultures, religion traits, and dated history.
Faith and rite list blocks are rewritten only after their values change.
Ordinary and eminent holy-site lists cannot contain the same site.

The religion and rite panels show static definitions and top-level character
history assignments. They do not simulate bookmark-specific faith/rite changes,
evaluate script triggers or DLC conditions, or provide a dedicated editor for
the new `history/faiths` database. Those scripts remain text-file work.
The existing culture, dynasty, and DNA tools continue reading game data rather
than embedding a 1.19 database. No binary DNA conversion is attempted.

## Verification

`npm run typecheck`, `npm test`, and `npm run build` pass.
The opt-in game-data audit copies all supplied religion, faith, and rite files
to a temporary directory, saves every definition unchanged, and checks each
file against its original bytes. It also checks representative faith, rite,
doctrine, tenet, succession-law, and ecclesiastical-history references.

Run it with a 1.20 game data directory in PowerShell:

```powershell
$env:CK3_GAME_DIR = 'C:\path\to\ck3-mod-base\base\game'
npm test
```

With the supplied tree, all 440 tests passed, including both integration checks.
The original game and mod-base files were read only. Visual browser testing
was unavailable because this session had no connected browser; an in-game
campaign load was not part of this verification.
